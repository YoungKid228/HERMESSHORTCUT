01 / ПОДГОТОВКА СЕРВЕРА

Сервер из аренды приходит «голым»: без обновлений, без утилит, с дефолтным SSH на 22-м порту и без защиты от перебора паролей. Сначала приводим машину в порядок.

1.1 Первый скрипт: swap, пользователь, заготовка конфига
wget -O /tmp/prepare-hermes.sh https://amorev.ru/misc/hermes/prepare-hermes-1.sh && sudo bash /tmp/prepare-hermes.sh
  • Создаёт /swapfile на 2 ГБ (fallocate → chmod 600 → mkswap → swapon) и добавляет его в /etc/fstab.
  • Ставит vm.swappiness = 80 — системе реже сбрасывать страницы в RAM.
  • Дважды спрашивает пароль (ввод скрыт) и сохраняет его хеш SHA-512 (openssl passwd -6) в /root/setup-data/password.hash с правами 600. Сам пароль нигде не остаётся.
  • Создаёт /root/setup-data/env.txt с шаблоном.
1.2 Заполняем env.txt вручную
sudo nano /root/setup-data/env.txt
ПараметрЧто вписать
TG_BOT_TOKENТокен бота от @BotFather
TG_CHAT_IDID чата (узнать через @userinfobot)
NEW_USERNAMEИмя будущего пользователя, по умолчанию hermes
SSH_PORTНовый SSH-порт, по умолчанию 2091

Сохраняем через Ctrl+O → Enter, выходим через Ctrl+X. Переменных для модели (endpoint, API-ключ) в env.txt нет — они задаются позже, при настройке агента. SERVER_IP в шаблоне отсутствует, но второй скрипт допишет его сам (через icanhazip.com с откатом на ifconfig.me и локальный hostname -I).

1.3 Второй скрипт: пользователь, SSH, UFW, fail2ban, уведомления
wget -O /tmp/prepare-hermes2.sh https://amorev.ru/misc/hermes/prepare-hermes-2.sh && sudo bash /tmp/prepare-hermes2.sh
  • Ставит пакеты: sudo ufw fail2ban curl ca-certificates openssh-server libpam-modules logrotate.
  • Создаёт пользователя hermes (useradd -m -s /bin/bash) и ставит пароль из хеша (chpasswd -e).
  • Даёт sudo без пароля: /etc/sudoers.d/hermes со строкой hermes ALL=(ALL:ALL) NOPASSWD:ALL, проверка — visudo -cf. Учтите: компрометация учётки даёт полный root.
  • Создаёт /home/hermes/.ssh с правами 700.
  • Правит /etc/ssh/sshd_config (с бэкапом): Port 2091, PermitRootLogin no, PasswordAuthentication yes, PubkeyAuthentication yes, ChallengeResponseAuthentication no, UsePAM yes. Валидация через sshd -t, потом рестарт.
  • UFW: ufw --force reset, политика deny incoming / allow outgoing, открыт только порт 2091/tcp.
  • fail2ban в /etc/fail2ban/jail.local: бан на час при 5 неудачных попытках за 10 минут, backend systemd, действие — бан через UFW, jail sshd на порту 2091.
  • Telegram-уведомления о входах: хук /usr/local/libexec/ssh-login-telegram.sh (права 700) + строка в /etc/pam.d/sshd. Логи — /var/log/hermes-ssh-login-telegram.log (600), ротация logrotate 14 дней.
  • Копирует env.txt в /home/hermes/env.txt, чтобы пользователь hermes мог прочитать конфиг без root.
  • Перезапускает SSH и печатает новый порт, пользователя, IP.
ВАЖНО

Не закрывай текущую SSH-сессию, пока не убедился, что вход с новым портом работает. Если конфиг sshd окажется невалидным, единственный способ вернуть доступ — консоль провайдера.

1.4 Проверяем вход под hermes

Открываем новый терминал (старый держим открытым) и подключаемся:

ssh hermes@<ВАШ_IP_СЕРВЕРА> -p 2091
whoami # должно быть hermes sudo -v # должно пройти без запроса пароля swapon --show # должен быть виден /swapfile sudo ufw status verbose sudo fail2ban-client status sshd

В ufw status должен быть открыт только порт 2091, а в списке jail fail2ban — Currently failed / Currently banned в нуле.

ЧТО ПОНАДОБИТСЯ

  • Сервер на Ubuntu 24.04 LTS — долгая поддержка, стабильные репозитории.
  • Root-доступ или пользователь с правами sudo.
  • 1 vCPU и 2 ГБ RAM для базовой установки; 4 ГБ — под фоновые задачи с тяжёлыми моделями.
  • Стабильный интернет и токен API: OpenAI-совместимый провайдер, Anthropic или локальный endpoint.
  • Базовое понимание cron и systemd.

03 / ПРОВАЙДЕР И МОДЕЛЬ

На экране баннер версии, список инструментов и навыков, и главное — агент говорит, что inference-провайдер ещё не настроен. Соглашаемся: Y и Enter (или просто Enter — Y стоит по умолчанию).

BASE URL · API-КЛЮЧ · ПРОВЕРКА

  • Base URL — адрес вместе с /v1 на конце. Если вписать https://ru.cheapvibecode.ru без /v1, запросы уйдут не туда и агент получит 404 на каждом шагу.
  • API-ключ — ввод скрыт, вместо символов звёздочки. Помечен как [optional]: локальному endpoint не нужен, внешнему — обязателен.
  • Проверка — Hermes сам дёргает https://ru.cheapvibecode.ru/v1/models и показывает 42 модели. Значит ключ рабочий, URL верный, провайдер отвечает по OpenAI-протоколу.

РЕЖИМ СОВМЕСТИМОСТИ

№РежимКогда нужен

2Chat CompletionsТо же принудительно — если автоопределение ошиблось

Рекомендация: выбирай 1 (Auto-detect) — просто Enter. Он сам определяет протокол по URL, и для проверенного endpoint с 42 видимыми моделями этого достаточно.

ВЫБОР МОДЕЛИ И TOOL-CALLING

Hermes показал все 42 модели и предлагает выбрать по номеру или ввести имя вручную. Из каталога берём MiniMax M3.1 Flash — пункт 40. Дальше reasoning effort — глубина размышления.

После настройки: Provider configured — провайдер встал. minimax-m3.1-flash внизу слева — активная модель, видна постоянно. ctx -- — провайдер не отдаёт лимит контекста в карточке (не ошибка, но повод задать контекст вручную). Строка ввода «Plan a feature, then build it step by step» — рекламный пример промпта, не ваш запрос. Подсказка про hermes acp — агент умеет работать как ACP-сервер (VS Code, Zed, JetBrains).

Главная проверка: умеет ли модель реально вызывать инструменты. Введите:

Вызови tool execute_code и выведи результат: print(2+2)

ПРОВАЙДЕРЫ

  • Nous Portal OAuth — вход через браузер, API-ключ не нужен. Самый быстрый путь.
  • OpenAI / Anthropic / OpenRouter — свой API-ключ.
  • Локальный endpoint — vLLM или Ollama на том же сервере или на отдельной машине.

04 / TELEGRAM-ШЛЮЗ

Агент на сервере полезен прежде всего тем, что пишет вам в чат и работает по расписанию. Для этого у Hermes есть фоновый шлюз — отдельный процесс, который держит подключение к Telegram.

Токен бота и chat id мы уже прописали в /root/setup-data/env.txt на этапе подготовки, а копия файла лежит в /home/hermes/env.txt — чтобы пользователь hermes мог прочитать конфиг без root.

hermes gateway restart

Телеграм не подключен — озадачим нашего агента. Отдаём ему всё, что он хочет, и перекладываем работу по настройке на него. Бот работает — теперь можно писать запросы агенту прямо в боте.

СЛЕДОМ

Тест 1 — обычный запрос в бота. Тест 2 — запрос с вызовом инструмента: агент должен вернуть результат, а не текст-обещание.
